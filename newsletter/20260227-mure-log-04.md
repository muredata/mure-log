## Data Reads

**01 / [Towards a Science of Scaling Agent Systems](https://research.google/blog/towards-a-science-of-scaling-agent-systems-when-and-why-agent-systems-work/)** — Yubin Kim et al. (Google Research)
Multi-agent systems excel at parallelizable tasks (81% improvement in finance) but fail on sequential work (70% decline in planning). "Centralized orchestrators cut error amplification 17.2x→4.4x." Agent effectiveness depends on alignment with task properties, not raw agent count.

**02 / [Your Agents Need Runbooks, Not Bigger Context Windows](https://gradientflow.substack.com/p/the-missing-layer-in-todays-agent)** — Ben Lorica
Context File Systems crystallize agent behaviors into reusable procedures after first execution, achieving "90% token reduction." Rather than expanding context, teams should build "versioned, reusable procedures" agents replay autonomously.

**03 / [Git for Data Applied: Comparing Git-like Tools That Separate Metadata from Data](https://motherduck.com/blog/git-for-data-part-2/)** — Simon Späti (MotherDuck)
LanceDB, Dolt, Nessie, and MotherDuck solve data versioning through metadata pointers, copy-on-write, or differential storage, enabling "zero-copy branching" without petabyte duplication.

**04 / [Duck, Dive, and Answer](https://motherduck.com/blog/duck-dive-and-answer/)** — Jordan Tigani
"Dives" (agent-generated SQL visualizations) achieve "95% text-to-SQL accuracy with proper context," enabling sales teams to query data independently.

**05 / [First Context Engineering Study — Are Semantic Layers Worth It](https://thenewaiorder.substack.com/p/first-context-engineering-study-are)** — Claire Gouze
Simple markdown rules outperform comprehensive semantic layers. "Schema+sample+rules.md hits 45% reliability" while full semantic approaches saw 3x slowdown and minimal improvements.

**06 / [Apache Gluten Engine Benefit to an Ingestion Workload](https://www.linkedin.com/pulse/apache-gluten-engine-benefit-ingestion-workload-binwei-yang-zyeqc/)** — Binwei Yang
Native code compilation for Spark SQL delivers "2-5x speedup on commodity hardware" through columnar optimization and predicate pushdown.

**07 / [dbt with Fabric Spark in Production](https://www.rakirahman.me/dbt-fabric-spark/)** — Raki Rahman
Local development environments (devcontainers) mirror production exactly, ensuring "identical behavior everywhere" through declarative pipeline management.

**08 / [Building an Obsidian RAG with DuckDB and MotherDuck](https://www.ssp.sh/blog/obsidian-rag-duckdb-sql/)** — Simon Späti
8,963 markdown notes converted to embeddings and indexed in DuckDB VSS, built with "Next.js+MotherDuck WASM" in 3-4 hours.

**09 / [Branching and Shallow Cloning in Lance: Towards a "Git for AI Data"](https://lancedb.com/blog/branching-and-shallow-clone/)** — Jack Ye (LanceDB)
Lance combines Iceberg branching with Delta shallow cloning, enabling "per-branch cost attribution" and full time travel without commit coupling.

**10 / [Mitchell Hashimoto's New Way of Writing Code](https://newsletter.pragmaticengineer.com/p/mitchell-hashimoto)** — Gergely Orosz
Background agents challenge traditional Git workflows. "Merge queues become untenable" as agent-generated contributions flood repositories, shifting practices toward "default deny" policies.
